# CD-AVC v2 adapter path

The v1 supervisor is provider-agnostic. The repository already includes an
OpenAI-compatible adapter so a local endpoint can be used without changing the
verification cage.

## Local model cache

Downloaded Hugging Face models must remain outside the repository. Point the
local runtime at the existing cache or model directory using that runtime's
configuration; CD-AVC only receives an HTTP endpoint and model identifier.

Do not commit `.cache/huggingface`, GGUF files, MLX weights, safetensors or
machine-specific paths.

## Small-model progression

Recommended order for local experiments:

1. deterministic mock provider;
2. small instruct or coder model;
3. Bonsai 2 2B/4B/9B model if its model-specific runtime works on the M3;
4. Bonsai 2 27B after memory and throughput are measured.

The current development machine has these relevant cached artifacts:

- Bonsai 2 9B GGUF: `Ternary-Bonsai-2-9B-PQ2_0-MTP-Q8_0.gguf`
- Bonsai 2 27B GGUF: `Ternary-Bonsai-2-27B-PTQ1_0.gguf`
- Qwen 2.5 7B Instruct GGUF: two split Q4_K_M files

CD-AVC can discover these files with `find_cached_model()` and construct a
server command with `build_llama_server_command()` in `cdavc.runtime`.

## Runtime compatibility warning

The installed Homebrew `llama-server` was smoke-tested against the cached
Bonsai 2 9B MTP file and rejected it with an invalid GGML tensor type. This is
consistent with the Bonsai model card: the custom `PTQ1_0`/`PQ2_0`/MTP formats
require the PrismML llama.cpp fork. The failure is a runtime compatibility
issue, not a CD-AVC provider failure.

Use the PrismML fork or its pinned prebuilt binary before attempting a Bonsai
run. Do not silently substitute stock llama.cpp and report the model as
working. The ordinary Qwen GGUF is retained as a possible stock-runtime
fallback for adapter testing.

The supervisor does not make model-specific assumptions. The provider must
return JSON of the form:

```json
{"files": {"src/example.py": "complete file contents"}}
```

The provider may only modify the implementation files declared by the task.
Tests are always controlled by the supervisor.
