The task is a closed set.

Before the model writes anything, the task declares one implementation file, the symbols that file must expose, the invariants to preserve and a retry budget. Everything else is out of scope by construction.

03/Gate one · locked tests

Seal the tests first.

CD-AVC hashes every locked test file before the run and again after it. If a single byte moved, the task fails before an assertion is allowed to run.

  • > sha-256
  • > before = after
  • > drift → reject
04/Gate two · AST contract

Parse is not proof.

The candidate must parse, and every symbol named in the contract must exist in the implementation file. A file that only looks plausible does not get past the check.

  • > ast.parse
  • > count_vowels required
  • > fail → restore
05/Execution · git worktree

Run it somewhere else.

The candidate runs in a fresh git worktree with the declared commands. The source tree is not the thing under test, and a failed attempt is thrown away.

  • > git worktree
  • > declared command
  • > source untouched
06/Gates three and four · the suite

Four gates, in order.

The targeted test runs first, then the optional hidden and negative checks, then the existing regression suite. A failure restores the original file and hands the error back to the model, inside the retry budget.

  • > targeted
  • > hidden · negative
  • > regression · retry ≤ 2
07/Verified copy-back

CD-AVC is a local, deterministic harness for testing patches produced by small coding models. Every patch is isolated in disposable git worktrees and measured against hash-locked tests.

HASH-LOCKED

Locked Test Immutability

Every test file is SHA-256 pre-hashed before execution and verified post-execution. If a model tries to cheat by weakening assertion logic, the run aborts instantly before assertions execute.

STATIC ANALYSIS

AST Symbol Verification

Syntactic validity is enforced prior to execution. Required function signatures, classes, and exported symbols must exist in the parsed tree or the patch is rejected immediately.

ISOLATION

Isolated worktrees

Execution never touches your working tree. Runs occur inside fresh git worktrees. Any failure restores original files without dirtying git status.

git worktree add /tmp/cdavc
EVIDENCE

Execution receipts

Passing runs generate machine-readable execution_log.json and human-diffable execution_report.md containing timing benchmarks, diff receipts, and hash records.
